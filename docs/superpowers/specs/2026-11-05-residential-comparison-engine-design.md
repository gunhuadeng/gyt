# 住宅市场比较法测算与报告工具设计

日期：2026-11-05  
状态：待用户批准  
目标产品：现有“估研台”原型的住宅税务估价改版

## 1. 意图

用户目前使用《住宅测算表.xlsx》完成税务场景下的住宅市场比较法测算，并按正式房地产估价报告格式输出结果。测算是最耗时且最容易出现字段、公式和报告金额不一致的环节。

本次改版要把现有通用比较法原型替换为符合实际业务流程的测算工作台：

1. 录入估价对象、三个可比实例和区域因素。
2. 按现有 Excel 中的明确公式计算价格修正。
3. 实时展示所有中间结果和异常。
4. 以原 Excel 为模板导出填写完成的副本。
5. 为后续生成正式 Word 报告提供同一套结构化数据。

## 2. 为什么采用该方案

用户的测算表不是普通的“案例加权平均”模型，而是一套带固定系数表、区域评分、装修重置价扣减和算术平均规则的专用模型。直接沿用现有原型的百分比修正和权重逻辑会得到错误结果。

原始 Excel 同时包含可见表、隐藏表、合并单元格、批注、图片、数据验证和公式。重新绘制工作簿会破坏其业务结构。因此采用：

- 网页端复刻确定性计算链；
- 原始 XLSX 作为导出模板；
- 只写入指定输入单元格；
- 保留其余工作簿部件；
- 打开文件时强制 Office/WPS 重新计算公式。

## 3. 目标

### 3.1 计算

- 完整复刻本次《住宅测算表.xlsx》的住宅市场比较法。
- 三个可比实例必须全部填写。
- 支持交易情况、市场状况、实体状况和区域状况修正。
- 交易情况和市场状况必须允许每个可比实例独立修正，不得锁定为 `1.000`。
- 支持结构、层次、房龄、朝向、东西至、装修和附属物因素。
- 输出每个案例的修正系数、比准价格、最终单价和总价。
- 以本次项目结果 `2,779 元/㎡`、`337,454 元` 作为黄金回归用例。

### 3.2 数据

- 将“证载总层数”和“楼层修正口径”分开存储。
- 将“地下层数”和“地上总层数”分开存储。
- 把估价对象和三个案例保存为同一套结构化数据。
- 自动保存、导入和导出项目 JSON。

### 3.3 导出

- 产出填写完成的 XLSX 副本，不修改用户原始文件。
- 尽量保留原始页眉、图片、隐藏工作表、合并单元格、批注和数据验证。
- Word 报告与 Excel 测算使用同一结果对象，避免金额不一致。

### 3.4 验证

- 输入不完整、楼层矛盾、价格离散度超标和公式异常必须明确提示。
- 每个最终数值都能追溯到输入字段、修正系数和公式。
- 楼层冲突经过用户确认后，不再重复报警，但保留审计说明。

## 4. 非目标

首版不包含：

- 收益法、成本法、假设开发法。
- 商业、办公、工业等其他物业类型。
- 批量项目或云端多人协作。
- 自动抓取房产网站、税务系统或地图数据。
- 由大模型自由决定估值、修正幅度或最终价格。
- 自动签署、盖章或替代注册房地产估价师。

## 5. 反目标

以下情况即使软件“能出文件”也视为失败：

- 网页结果与 Excel 公式结果不一致。
- 正式报告金额、单价或人民币大写与测算表不一致。
- 把证载层数 `18/19` 直接用于顶楼判断。
- 导出时丢失隐藏表、图片或关键公式。
- 用不可解释的 AI 估算替代明确计算。
- 覆盖或修改用户提供的原始 Excel/Word 文件。

## 6. 约束

- 当前应用为 Windows 本地 Web 原型。
- 数据属于估价业务资料，默认只保存在本机。
- Excel 原表由 WPS 保存，包含 VML、绘图和隐藏表。
- 正式报告源文件目前是旧版二进制 `.doc`，无法无损转换成现代 `.docx`。
- 要完整保留正式报告版式，需要用户另外提供 `.docx` 模板或由 WPS 另存为 `.docx`。
- 所有计算使用十进制定点数，不使用二进制浮点数直接做金额判断。

## 7. 已比较的方案

### 方案 A：原 Excel 作为模板，网页复刻计算（已选择）

- 网页负责结构化录入、实时计算和校验。
- 导出时复制原始 XLSX，只修改输入单元格并设置 `fullCalcOnLoad`。
- 保留隐藏表、图片、批注、样式和未修改公式。
- 优点：计算可复核、Excel 保真度高、无需安装 Office 服务。
- 缺点：必须维护字段到单元格的映射，模板改版时需要更新映射。

选择原因：最符合用户现有工作方式，也最容易核对网页结果和 Excel 结果。

### 方案 B：完全重新生成 Excel

- 使用程序重新绘制所有工作表和格式。
- 优点：结构更现代。
- 缺点：会丢失现有隐藏表、图片、批注和业务布局，也容易遗漏公式。

未选择。

### 方案 C：网页调用 WPS/Excel 自动打开并计算

- 使用桌面 Office 自动化填写和保存。
- 优点：可直接复用软件计算引擎。
- 缺点：依赖安装、弹窗、文件占用和权限，难以稳定运行。

未选择。

## 8. 楼层口径

本项目的楼层字段必须拆分为：

```text
证载总层数：19
地下层数：1
地上总层数：18
所在楼层：18
楼层修正口径：18/18（顶层）
```

界面和报告显示可以是：

```text
18/19（地下一层、地上18层、所在层18层、顶层）
```

计算规则只使用地上总层数和所在楼层，不将地下室计入住宅楼层修正。

本次估价对象为地上18层中的第18层，因此：

```text
高层顶层系数 = 100 + (18 - 6) × 0.2 - 3 = 99.4%
```

## 10. 计算规则

所有中间值都保留公式轨迹。金额和系数按原 Excel 的 ROUND 规则处理。

### 10.1 区域因素

```text
区域项得分 = 评分表[因素][等级]
区域总分 = Σ区域项得分
P4区域状况修正 = ROUND(估价对象区域总分 / 案例区域总分, 3)
```

允许估价师显式覆盖自动结果，并记录覆盖原因。

### 10.2 层次因素

建筑类型分为普通多层、电梯多层、小高层/高层。

高层规则：

```text
1层 = 97.5
2层 = 98.0
3层 = 98.5
4层 = 99.0
5层 = 99.5
6层 = 100.0
7层 = 100.2
8层至顶层下一层 = 100 + (所在层 - 6) × 0.2
顶层 = 100 + (地上总层数 - 6) × 0.2 - 3
```

普通多层和电梯多层使用工作簿中的矩阵表。

### 10.3 其他实体因素

```text
结构系数：钢混 108；砖混/混合 100；砖木 95
成新系数 = 100 + (案例建成年代 - 估价对象建成年代) × 0.5
朝向系数：北96；西98；东99；一室朝南100；二室朝南101；三室朝南102
东西至：仅联排别墅修正；东边户106；中间户100；西边户104
建筑面积系数：估价师输入，默认100，按项目实际情况修正
```

### 10.4 实体状况综合

```text
实体系数百分比 =
  ROUND(面积 × 结构 × 层次 × 成新 × 朝向 × 东西至 / 10^10, 2)

P3实体状况修正 =
  ROUND(估价对象实体系数百分比 / 案例实体系数百分比, 3)
```

### 10.5 装修和附属物

```text
装修成新率 = 1 - 已使用年限 / 耐用年限
Va单位面积装修重置价 =
  ROUND(案例装修单价 × 案例装修成新率
        - 估价对象装修单价 × 估价对象装修成新率, 0)

Vb单位面积附属物扣减值 = 用户输入或 0
```

首版不推测附属物面积计算公式，只保留直接输入值和系数表参考，避免凭空增加业务规则。

### 10.6 比准价格

```text
P = ROUND(P1 × P2 × P3 × P4, 3)
Vs修正前金额 = ROUND(案例成交单价 × P, 0)
Vn比准价格 = Vs修正前金额 - Va - Vb
```

其中：

- `P1` 为该案例的交易情况修正系数。
- `P2` 为该案例的市场状况修正系数。
- 两项都以 `1.000` 为不修正基准。
- 两项均允许估价师独立填写其他正值；软件只校验必须大于 0，不强行限制为固定档位。
- 当 P1 或 P2 不等于 `1.000` 时，界面同时显示对应百分比，例如 `1.025 = 102.5%`。
- 当 P1 或 P2 不等于 `1.000` 且未填写修正说明时给出复核提示，但不阻止继续测算。
- 导出 Excel 时，P1 写入 `B54:E54`，P2 写入 `B55:E55`。
- 导出 Word 时，如果采用非中性修正，必须将对应修正说明写入交易情况或市场状况章节，避免报告中只有数字没有依据。

### 10.7 最终结果

```text
评估单价 = ROUND((VnA + VnB + VnC) / 3, 0)
评估总价 = ROUND(评估单价 × 估价对象建筑面积, 0)
价格离散度 = MAX(VnA,VnB,VnC) / MIN(VnA,VnB,VnC) - 1
```

价格离散度超过 10% 时提示复核，但不直接阻止导出。

## 12. Excel 导出

导出流程：

1. 读取用户指定的原始 XLSX。
2. 将填写值转换到 `1-1 测算表` 对应输入单元格。
3. 复制原工作簿的全部包部件。
4. 仅替换目标工作表 XML 中指定单元格的值。
5. 将 `calcPr` 设置为打开时完整重算。
6. 输出新文件，文件名附带报告编号和“已填写”。

原始文件只读，永不覆盖。

待实现时需要通过测试确定并固定以下输入映射：

- D6:G15 的基本信息和装修字段。
- D16:G30 的区域因素等级。
- D31:G32 的交易时间和成交单价。
- B43:E43 的面积修正。
- B45:E48 与楼层、朝向、东西至有关的可覆盖字段。
- B51:E52 的装修价格和成新率。
- B54:E55 的交易情况和市场状况修正。
- B58:E58 的附属物扣减。

公式单元格不由网页直接覆盖，除非用户明确选择“高级覆盖”。
